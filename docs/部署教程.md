# 部署教程：从零到"别人打开链接就能用"

这份文档是**操作手册**，按顺序做完即可。全程大约 15 分钟，不需要买服务器、不需要域名、不需要懂后端。

> **本仓库信息**
> 代码地址：<https://github.com/xd335/ai-ppt-studio>
> 上线后的地址：<https://xd335.github.io/ai-ppt-studio/>
>
> 下面的命令里如果出现 `你的用户名`，换成 `xd335` 就是本项目的实际地址。

---

## 0. 先建立正确预期

这是一个**纯静态站点**：没有后端、没有数据库、没有构建步骤。

```
index.html          ← 入口
assets/             ← 样式、脚本、内置的 pptxgenjs
```

把这两样放到任何一个"能通过网址访问文件夹"的地方，它就上线了。所以下面所有平台（GitHub Pages、Gitee Pages、Vercel、Netlify、自己的 Nginx、对象存储）的操作逻辑都一样：**上传文件夹 → 开启静态托管**。

> 数据存在**访问者自己的浏览器**里（`localStorage`）。你没有服务器，也不需要有——不收集任何用户数据，这是设计上的选择。

## 1. 本机先跑通（5 分钟）

别急着上网部署，先确认东西在你电脑上是好的。

### 1.1 直接双击

打开解压后的文件夹，双击 `index.html`。

### 1.2 或者起个本地服务（推荐）

浏览器对 `file://` 有一些额外限制，起个服务最接近线上环境：

```bash
cd ai-ppt-studio

python -m http.server 8080
# 或者： npx serve .
```

打开 <http://localhost:8080>。

### 1.3 上线前的自检清单

- [ ] 打开后能看到一份 15 页的示例演示（不是空白）
- [ ] 左侧点「用本地模板生成」，页面数量会变
- [ ] 点右上角「下载 PPTX」，能得到一个能打开的 `.pptx`
- [ ] 点「演示」，方向键能翻页，Esc 能退出

四项都过，再往下走。

## 2. 发布到 GitHub（推荐）

### 2.1 准备账号

没有账号先注册：<https://github.com/signup>。建议顺手把邮箱验证了，否则 Pages 可能不给开。

### 2.2 新建仓库

1. 打开 <https://github.com/new>
2. **Repository name** 填 `ai-ppt-studio`（或你喜欢的名字，会影响网址）
3. 可见性选 **Public**
   > 免费账号的 GitHub Pages 只对公开仓库开放；私有仓库开 Pages 需要付费计划。
4. **不要**勾选 "Add a README file"、".gitignore"、"license" —— 项目里已经有了，勾了会在推送时冲突
5. 点 **Create repository**

### 2.3 把代码传上去

三种方式，选一种就行。

#### 方式 A：网页拖拽（最简单，适合不想碰命令行）

1. 在刚建好的仓库页面点 **uploading an existing file**
2. 把 `ai-ppt-studio` 文件夹**里面的内容**（不是文件夹本身）全部拖进浏览器
   - 至少要有：`index.html`、`assets/`、`README.md`
   - 想要部署脚本也一起传：`.github/`、`.nojekyll`
3. 底部填一句提交说明，点 **Commit changes**

> 拖拽的坑：浏览器对隐藏文件（`.github`、`.nojekyll`、`.gitignore`）支持不稳定，可能传不上去。如果后面 Pages 部署失败，多半是这个原因，改用方式 B。

#### 方式 B：命令行（推荐，一步到位）

在本机装好 Git 后，进入项目文件夹：

```bash
cd ai-ppt-studio

# 项目里已经初始化好仓库、提交记录和 v1.0.0 标签，只需接上远端
git remote add origin https://github.com/你的用户名/ai-ppt-studio.git
git push -u origin main
git push origin v1.0.0
```

如果你拿到的是没有 `.git` 的干净副本，就从零开始：

```bash
cd ai-ppt-studio
git init -b main
git add .
git commit -m "feat: AI PPT Studio 首个版本"
git branch -M main
git remote add origin https://github.com/你的用户名/ai-ppt-studio.git
git push -u origin main
```

> 推送时要验证身份。GitHub 已经不支持账号密码，请用 **Personal Access Token** 当密码（Settings → Developer settings → Personal access tokens → Fine-grained tokens，勾选该仓库的 Contents: Read and write），或者用 GitHub Desktop 登录后推送。
>
> 首次提交如果提示 `Author identity unknown`，先设置一次：
> ```bash
> git config --global user.name "你的名字"
> git config --global user.email "你的邮箱"
> ```

#### 推不上去怎么办：`Could not resolve host: github.com`

这是国内常见的 DNS 污染，`github.com` 解析失败，但 `api.github.com`、`ssh.github.com` 往往还能通。这种情况不要死磕 HTTPS，改走 **SSH over 443**：

```bash
# 1. 生成密钥（已有可跳过，一路回车即可）
ssh-keygen -t ed25519 -C "你的邮箱"

# 2. 复制公钥，粘贴到 GitHub → Settings → SSH and GPG keys → New SSH key
type %USERPROFILE%\.ssh\id_ed25519.pub     # Windows
# cat ~/.ssh/id_ed25519.pub                # macOS / Linux

# 3. 测试（走 443 端口，绕开 22 端口被墙）
ssh -T -p 443 git@ssh.github.com
# 看到 "Hi 你的用户名! You've successfully authenticated" 就成了

# 4. 把远端换成 SSH 地址，再推
git remote set-url origin ssh://git@ssh.github.com:443/你的用户名/ai-ppt-studio.git
git push -u origin main
```

如果你有可用的本地代理，也可以只给 git 走代理：

```bash
git config --global http.proxy  http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
# 用完撤销，否则访问内网仓库会失败
git config --global --unset http.proxy
git config --global --unset https.proxy
```

#### 方式 C：GitHub Desktop

1. 安装 <https://desktop.github.com/>
2. **File → Add local repository**，选中 `ai-ppt-studio` 文件夹
3. 右上角 **Publish repository**，取消勾选 "Keep this code private"

### 2.4 开启 GitHub Pages

项目里已经放好了 `.github/workflows/deploy.yml`，**推上去之后通常不用你做任何事**。

**验证方式一（自动，推荐）**

1. 打开仓库 → **Settings → Pages**
2. **Source** 选 **GitHub Actions**
3. 打开 **Actions** 标签页，应该能看到一个叫 "Deploy to GitHub Pages" 的任务在跑
4. 等它变成绿色对勾（约 1 分钟），回到 Settings → Pages，顶部会出现
   `Your site is live at https://你的用户名.github.io/ai-ppt-studio/`

**验证方式二（手动分支部署，不想用 Actions 就走这条）**

1. **Settings → Pages**
2. **Source** 选 **Deploy from a branch**
3. **Branch** 选 `main`，目录选 `/ (root)`
4. **Save**，等 1—2 分钟

> 仓库根目录的 `.nojekyll` 是一个空文件，作用是告诉 GitHub 不要用 Jekyll 处理这个站点。它在，`assets/` 这类目录就不会被意外忽略。

### 2.5 打开看看

访问 `https://你的用户名.github.io/ai-ppt-studio/`。

第一次部署有 1—2 分钟延迟，如果 404，先等一会儿，再按 `Ctrl+F5` 强制刷新（Pages 有 CDN 缓存）。

## 3. 同步一份到 Gitee（国内打开更快）

GitHub Pages 在国内经常慢，建议加一个 Gitee 镜像：

1. 注册并实名认证 <https://gitee.com>（Gitee Pages 需要实名）
2. 右上角 **+ → 新建仓库**，名称同样填 `ai-ppt-studio`，**不要**初始化
3. 页面下方 **导入已有仓库**，粘贴你的 GitHub 地址，等待拉取完成
4. 进入 Gitee 仓库 → **服务 → Gitee Pages**
5. 部署分支选 `master`（或 `main`），部署目录留空，勾选 **强制使用 HTTPS**
6. 启动后得到 `https://你的用户名.gitee.io/ai-ppt-studio/`

> Gitee Pages 不会自动跟着 GitHub 更新，每次改完代码要去点一次「更新」；免费版每次更新也都要手动确认。

## 4. 绑定自己的域名（可选）

假设你有 `ppt.example.com`：

**GitHub**

1. 在仓库根目录新建文件 `CNAME`，内容只有一行：`ppt.example.com`
2. 在域名服务商处添加解析：
   - 类型 `CNAME`，主机记录 `ppt`，记录值 `你的用户名.github.io`
3. 回到 **Settings → Pages**，填入 Custom domain，勾选 **Enforce HTTPS**
4. 证书签发要几分钟到几小时，等它变成 "✅ DNS check successful"

**Gitee**：Gitee Pages 的自定义域名是付费功能，免费版跳过这一步。

## 5. 以后怎么更新

```bash
# 改完代码
git add .
git commit -m "调整封面版式"
git push
```

用 Actions 的话，推送后自动重新部署，1 分钟左右生效。改完记得刷新时清缓存，或者在地址后面加个 `?v=2` 试试是不是缓存问题。

**回滚**：打开 **Actions** → 找到上一次成功的部署 → 右上角 **Re-run all jobs**；或者 `git revert` 后推一次。

## 6. 常见问题

**打开是白屏 / 只有 HTML 没有样式**

九成是文件没传全。检查仓库里是否存在 `assets/css/app.css`、`assets/js/app.js`。GitHub 网页上传时，文件夹是逐层创建的，容易漏。

**Pages 设置里没有 "GitHub Actions" 这个选项**

仓库是私有的，或者账号没验证邮箱。改成 Public 并验证邮箱即可。

**Actions 报错 `Resource not accessible by integration`**

Settings → Actions → General → Workflow permissions，选 **Read and write permissions**，保存后重新跑。

**部署成功但访问 404**

- 地址少写了仓库名：应该是 `https://用户名.github.io/仓库名/`
- 分支/目录选错了：根目录是 `/ (root)`，不是 `/docs`
- 还没构建完：等 1—2 分钟

**页面能打开，但点「下载 PPTX」没反应**

浏览器拦截了下载（尤其是有弹窗拦截插件时）。地址栏右侧会有一个小图标，允许即可。

**生成大纲时报「无法连接接口」**

这是浏览器跨域（CORS）限制，和服务商策略有关。解决办法：改用「本地模板」，或者自建一个转发代理（README 里有 Cloudflare Worker 示例）。

**换了台电脑，之前的内容没了**

内容存在浏览器本地，不会跟着账号走。换设备前用「导出」存成 `.json`，到新设备「导入」。

## 7. 发出去之前的最后检查

- [ ] 手机上打开一次，确认能滚动、能点按钮（工具本身按桌面设计，手机只做可读性兜底）
- [ ] 用无痕窗口打开一次，确认不依赖你本机的缓存和登录状态
- [ ] 把 `README.md` 里的仓库地址、截图换成你自己的
- [ ] 确认 `examples/` 里的样张是你想展示的效果
- [ ] 如果填过 API Key，确认没有把它写进任何提交的文件里（Key 只存在浏览器 localStorage，不在代码里）

## 附：三种托管方式的对比

| | GitHub Pages | Gitee Pages | Vercel / Netlify |
| --- | --- | --- | --- |
| 费用 | 免费 | 免费 | 免费额度 |
| 国内速度 | 慢，时好时坏 | 较快 | 一般 |
| 自动部署 | Actions 可配 | 手动点更新 | 推上去就自动 |
| 自定义域名 | 免费 | 付费 | 免费 |
| 适合 | 开源项目主页 | 国内分享 | 想要更快更稳 |

这个项目三者都支持，因为不需要任何构建命令——**Build command 留空，Output directory 填 `.` 或 `/`** 即可。
